Foundations

Introduction

Deep learning is machine learning using neural networks with many layers. The key shift from older methods: instead of a person hand-designing "features" (edges, shapes, keywords), the network learns what features matter directly from raw data. This became practical around 2012, when a network called AlexNet nearly halved the error rate on ImageNet (a 14-million-image benchmark) — the moment that convinced the field deep networks actually work at scale.

TermPlain meaning
Neural networkA stack of simple math units, loosely inspired by neurons, that together can approximate very complex functions.
Feature learningThe network figures out on its own which patterns in the data are useful, instead of being told.
Supervised / unsupervisedSupervised = you have labels (correct answers) to learn from. Unsupervised = you don't, and the model finds structure by itself.
ImageNet / ILSVRCThe famous 1000-class, 14-million-image benchmark that became deep learning's proving ground.

Foundations

Feedforward Neural Networks

The smallest building block is a perceptron: it multiplies each input by a weight, adds them up, and fires "yes" or "no" depending on the sign of the result. A single perceptron can only draw a straight-line boundary, so it famously can't solve the XOR problem (data arranged so no single line separates the classes) — this failure nearly ended AI research funding in the 1970s ("the AI winter"). The fix: stack perceptrons into layers — a Multi-Layer Perceptron — which can bend that boundary into any shape. Backpropagation is simply the bookkeeping trick that computes, layer by layer working backward from the error, exactly how much to nudge every single weight.

Notation you'll see x = input   w = weight   b = bias (an extra learnable offset)   ŷ ("y-hat") = the network's prediction   η (eta) = learning rate, the size of each update step   ∇ (nabla) = gradient, the direction that increases the loss fastest — you step opposite to it
TermPlain meaning
PerceptronWeighted sum of inputs → sign decides the class. The simplest possible "neuron."
XOR problemA dataset no single straight line can separate — proof one perceptron isn't enough.
Multi-Layer Perceptron (MLP)Perceptrons stacked in layers, which can now bend decision boundaries into curves.
Universal Approximation TheoremOne hidden layer, if wide enough, can approximate almost any function — a guarantee of existence, not a recipe.
BackpropagationThe chain-rule bookkeeping that computes every weight's update by working backward from the loss.
Vanishing / exploding gradientMultiplying many small (or large) numbers during backprop makes updates shrink to ~0 (or blow up) in deep networks.

Loss Functions & Optimization

The loss is one number that says "how wrong is the network right now." Different tasks need differently-shaped losses: regression (predicting a number) typically uses squared error; classification (predicting a category) uses cross-entropy. Both actually come from the same idea — Maximum Likelihood Estimation: pick the loss that makes your training data the most probable outcome under some assumed noise model (Gaussian for regression, categorical for classification). Once you have a loss, optimization is the family of algorithms that nudge the weights to shrink it — from plain gradient descent up to modern methods like Adam that give every weight its own adaptive step size.

Notation you'll see L(w) = the loss, written as a function of the weights   p(y|x) = "probability of label y given input x"   argmin / argmax = "the value that makes this smallest / largest"   μ (mu) = momentum coefficient (typically 0.9)   ρ (rho) = decay rate in RMSProp/Adadelta   β (beta) = precision (1/variance) in the Gaussian derivation
TermPlain meaning
L2 / MSE lossSquared difference between prediction and target — the natural loss for regression.
Cross-entropy lossThe natural loss for classification — directly tied to how "surprised" the model is by the true label.
Hinge lossUsed with SVM-style classifiers; only penalizes points that are wrong or too close to the boundary.
SubgradientA stand-in for the gradient at "kinks" (like ReLU's corner at 0) where no single slope exists.
Batch / stochastic / mini-batch GDUse all data / one sample / a small random subset to estimate the gradient at each step.
Momentum / NesterovKeep a running average of past gradient directions so you don't zig-zag as much.
AdaGrad / RMSProp / AdamGive each individual weight its own adaptive learning rate based on its gradient history.

Activation Functions & CNNs

The activation function is the small non-linear decision every neuron applies after summing its inputs — without it, stacking 100 layers is mathematically identical to stacking one. Early choices (sigmoid, tanh) squash values into a narrow range and "saturate," which is what causes vanishing gradients; ReLU (just "zero if negative, otherwise keep the value") fixed this and enabled truly deep networks. For images specifically, Convolutional Neural Networks exploit the fact that nearby pixels are related: instead of connecting every pixel to every neuron, a small filter (e.g. 3×3) slides across the whole image reusing the same weights everywhere — this is what "convolution" means here.

Notation you'll see f(x) = the activation function   f′(x) = its derivative (needed for backprop)   σ (sigma) = the sigmoid function   max(0,x) = ReLU, in words: "zero, or x, whichever is bigger"   α (alpha) = the small slope given to negative inputs in Leaky ReLU
TermPlain meaning
Sigmoid / tanhS-shaped curves squashing output to (0,1) or (−1,1); both saturate and cause vanishing gradients.
ReLUmax(0, x) — fast, avoids vanishing gradients for positive inputs, the modern default.
Dying ReLUA neuron stuck always outputting 0, so it can never update again.
Leaky / Parametric ReLU, ELUVariants that give negative inputs a small non-zero slope, avoiding the "dying" problem.
Convolution / filter / kernelA small weight grid slid across the whole image, reused at every position ("weight sharing").
Padding / stride / dilationControls for output size, step size between filter positions, and spacing within the filter.
1×1 convolutionMathematically a fully-connected layer applied per-pixel — used to compress channels cheaply.
Pooling (max/average)Shrinks feature maps by summarizing small neighborhoods to one value.

Left: the activation shapes your course compares — notice how sigmoid and tanh flatten out ("saturate") at the extremes, while ReLU stays a straight, unsaturated line for any positive input. Right: what "convolution" physically means — the same small filter window slides across the input, producing one output value per position.

Regularization

A model can fail in two opposite ways: underfitting (too simple, misses real patterns — "high bias") or overfitting (memorizes noise in the training data instead of learning general patterns — "high variance"). Regularization is any technique that deliberately holds a model back from perfectly fitting its training data, trading a little training accuracy for much better performance on new, unseen data. The simplest version is just watching a validation loss curve and stopping the moment it starts creeping back up (early stopping).

Notation you'll see bias² + variance + irreducible error = the three-way split of total expected error   λ (lambda) = strength of a regularization penalty   p(w) = your prior belief about what weights should look like (e.g. "probably small")   MAP = Maximum A Posteriori, i.e. loss + penalty framed as a probability statement
TermPlain meaning
Bias–variance tradeoffSimplifying a model reduces variance but raises bias, and vice versa — you can't minimize both freely.
Model capacity / VC dimensionA formal way to measure "how many different patterns can this model possibly represent."
Early stoppingHalt training right when validation loss stops improving, before it starts rising again.
Data augmentationArtificially create more training examples via label-preserving transforms (crop, flip, rotate, jitter).
L2 regularization / weight decayAdd a penalty for large weights to the loss — encourages simpler, smaller-weight solutions.

Left: the classic "dartboard" picture of bias vs. variance — low bias/low variance (top-left) is the goal; every other quadrant misses in a different way. Right: the telltale overfitting signature — training loss keeps falling while validation loss turns back upward; the dashed line marks where you'd want to stop.

Common Practices

This lecture is the field-tested checklist for not wasting weeks of compute on a broken setup. Before any real training: verify your gradients are actually correct using tiny numerical checks, and confirm the network can memorize a handful of examples (if it can't even overfit 10 samples, something is broken). During training: watch the loss curves and never, ever look at the test set until the very last step of the entire project — that's the one rule this lecture repeats the most.

Notation you'll see h = a tiny step size used to numerically estimate a gradient by nudging a weight slightly   α (alpha) = significance level in a statistical test (e.g. 0.05)   t-test = a statistical test asking "are these two results different enough to not be chance?"
TermPlain meaning
Gradient checkingCompare your backprop gradient against a slow numerical estimate to catch implementation bugs.
The "test set vault"Never touch the test set during development — only open it once, at the very end.
Class imbalance fixesResampling, oversampling minority classes, or weighting the loss by inverse class frequency.
EnsemblingTrain several models and combine their predictions — reliably boosts accuracy a little further.
Accuracy / Precision / Recall / F1 / ROCDifferent lenses on "how good is the model," each sensitive to different kinds of mistakes.
Cross-validationSplit data into k folds, train k times, so every sample gets used for both training and testing.
Significance testingConfirming that "my model is better" isn't just random luck from one lucky training run.

Architectures

This is a "greatest hits" tour of famous CNNs, each solving a specific problem left by the last. LeNet (1998) proved the convolution-pooling recipe works, on handwritten digits. AlexNet (2012) scaled it up with ReLU, dropout, and GPUs, halving the ImageNet error rate overnight. VGG showed that simply stacking small 3×3 filters, very deep, works well. GoogLeNet/Inception let the network choose its own mix of filter sizes at each layer instead of fixing it by hand. ResNet solved a strange discovery — that just adding more layers eventually made training worse, not better — by adding "skip connections" that let gradients flow straight through.

ArchitectureKey idea it introduced
LeNet-5 (1998)The original conv → pool → conv → pool → classify template.
AlexNet (2012)ReLU + dropout + GPU training at scale — the breakthrough moment.
Network-in-NetworkIntroduced 1×1 convolutions and global average pooling.
VGGVery deep, but only ever uses simple, uniform 3×3 filters.
GoogLeNet / InceptionRuns several filter sizes in parallel per layer and lets training decide what's useful.
ResNet (residual/skip connections)Adds the input straight to the output of a block, so gradients have a direct path backward — enables truly deep (100+ layer) networks.
DenseNetConnects every layer to every later layer — maximal feature reuse, fewer parameters.
Neural Architecture Search (NAS)Use reinforcement learning or genetic algorithms to design the architecture itself.

Recurrent Neural Networks & LSTMs

For sequences — text, speech, sensor streams — order matters, and a plain feedforward network has no memory of what came before. A Recurrent Neural Network (RNN) carries a "hidden state" forward step by step, like a running notebook it updates after reading each new word. The catch: over long sequences, the same vanishing-gradient problem from lecture 2 returns with a vengeance, so basic RNNs forget things that happened many steps ago. LSTM fixes this with a separate "cell state" — a conveyor belt of memory — plus three gates that explicitly learn what to forget, what to add, and what to output at every step.

Notation you'll see h_t = hidden state at time t (the "notebook")   x_t = input at time t   W_hh, W_xh, W_hy = the (shared, reused-every-step) weight matrices   C_t = LSTM cell state (long-term memory)   f_t, i_t, o_t = forget / input / output gates, each a number between 0 and 1
TermPlain meaning
Hidden state updateNew hidden state = a squashed mix of the previous hidden state and the new input.
BPTT (Backprop Through Time)Backpropagation unrolled across every time step of the sequence.
Truncated BPTTOnly backpropagate through a limited recent window, for efficiency on long sequences.
Long-term dependency problemPlain RNNs struggle to connect information that's many steps apart.
LSTM cell stateA separate memory highway that gradients can cross without shrinking — the fix for vanishing gradients.
Forget / input / output gatesLearned "valves" (0 to 1) controlling what leaves, enters, and is read from the cell state.

Left: the same block "A" is reused at every time step — this weight-sharing is what lets an RNN handle sequences of any length. Right: inside an LSTM, three gates (forget/input/output) each decide, using a sigmoid, how much of the cell-state highway to let through.

Visualization & Attention Mechanisms

This lecture has two halves. The first is about peeking inside a trained network — visualizing which filters activated, which pixels drove a decision (saliency maps), what a neuron's "favorite" input looks like. The second, more important half is attention: rather than squashing an entire input sentence into one fixed-size vector (which loses information for long sentences), let the decoder look back at every position of the input and learn, freshly at each output step, which ones matter most right now. The Transformer takes this to its logical extreme — build the entire network out of attention alone, no recurrence needed at all — and now underlies almost all modern language models (including BERT).

Notation you'll see α_t,i (alpha) = attention weight — how much output step t "looks at" input position i   Q, K, V = Query / Key / Value vectors — "what I'm looking for," "what I offer," "what I'll give you if matched"   d_k = dimensionality of the key vectors, used to rescale the scores so they don't grow too large
TermPlain meaning
Saliency map / Grad-CAMHighlights which input pixels most influenced the network's decision.
Seq2seq (encoder–decoder)Encoder reads the whole input into hidden states; decoder generates the output from them.
Dynamic context vector / alignmentInstead of one fixed summary vector, a fresh weighted mix of all encoder states at every output step.
Self-attentionEvery word in a sentence directly attends to every other word — resolves things like pronoun reference.
Scaled dot-product attentionThe Transformer's core formula: match queries to keys, scale, softmax, then mix the values.
Multi-head attentionRun several attention "lenses" in parallel so different heads can specialize in different relationships.
Positional encodingSince attention has no built-in sense of order, word position is added in explicitly.
BERTA Transformer pre-trained on massive unlabeled text by guessing masked-out words.

Segmentation & Object Detection

Three related but distinct tasks: classification asks "what's in this image," segmentation asks "which class does each individual pixel belong to," and object detection asks "where is each object, draw a box around it." Segmentation networks use an encoder–decoder ("hourglass") shape: shrink the image down through convolutions to understand what is there, then grow it back up to paint a label on every pixel, using skip connections to recover the fine where detail lost during shrinking (this is exactly what U-Net does). Object detection evolved from painfully slow sliding windows, through the R-CNN family (each version removing one more bottleneck), to single-shot detectors like YOLO that predict every box in one forward pass.

TermPlain meaning
Fully Convolutional Network (FCN)Replace the final classifier with convolutions, so output is a full spatial map, not one label.
Encoder–decoder / U-Net / SegNetShrink then regrow spatial resolution, using skip connections to keep fine detail.
Upsampling (transpose conv / unpooling)The decoder's way of growing a small feature map back to full image size.
Dilated (atrous) convolutionSpread out a filter's sample points to see a wider area without adding parameters.
Sliding windowThe brute-force original approach: test every possible box location — very slow.
R-CNN → Fast → Faster R-CNNEach version shares more computation across proposed boxes, removing a bottleneck each time.
YOLO / single-shot detectorsPredict all boxes and classes in one single forward pass — real-time capable.

Learning Paradigms

Deep Reinforcement Learning

A completely different setup: there's no fixed dataset of labeled examples. Instead, an agent takes actions inside an environment, receives a reward signal, and must learn — purely through trial and error — which actions lead to the best long-term payoff. This is formalized as a Markov Decision Process: the next state only depends on the current state and action, not the whole history. Deep Q-Learning (famous for learning to play Atari games from raw pixels) uses a neural network to estimate the long-term value of every possible action, then two engineering tricks — a slowly-updated target network and a replay memory of past experiences — to keep training from spiraling out of control.

Notation you'll see s = state   a = action   r = reward   π (pi) = policy, the agent's strategy for picking actions   γ (gamma) = discount factor (0 to 1) — how much future reward matters vs. immediate reward   V(s) = value of being in state s   Q(s,a) = value of taking action a while in state s
TermPlain meaning
Markov Decision Process (MDP)The formal state → action → reward → next-state loop that RL problems are framed as.
Value function / Bellman equation"How good is this state" defined recursively in terms of the next state's value.
Policy iterationAlternate between scoring the current strategy and improving it, until it stops changing.
Q-learningLearn the action-value function directly, without needing to know the environment's rules in advance.
Deep Q-Network (DQN)Use a neural network (fed raw pixels) to estimate Q-values — the system that mastered Atari games.
Target network / experience replayTwo stability tricks: freeze a copy of the network briefly, and learn from a shuffled memory of past experiences rather than only the most recent one.
Policy gradient / REINFORCEDirectly adjust the policy's parameters using ordinary backpropagation.
AlphaGo / AlphaZeroCombined deep RL with tree search to beat professional Go players, then generalized to other games via self-play alone.

Unsupervised Deep Learning

Learning without any labels — finding structure the data has on its own. An autoencoder squeezes the input down to a small compressed code, then tries to reconstruct the original from just that code — forcing the compressed code to capture only what's essential. A Variational Autoencoder (VAE) makes that compressed code probabilistic (a small cloud of possibility instead of one fixed point), which makes it possible to sample entirely new, never-seen data from it. A Generative Adversarial Network (GAN) takes a completely different approach: pit two networks against each other — a generator trying to fake realistic data, and a discriminator trying to catch the fakes — like an art forger versus an art critic, each one improving because of the other.

Notation you'll see z = the compressed "latent" code   μ, σ (mu, sigma) = the mean and spread of the latent distribution a VAE learns   KL(p,q) = a measure of how different two probability distributions are   θ^G, θ^D = generator / discriminator parameters   p_data, p_z = the real-data distribution and the noise distribution fed to the generator
TermPlain meaning
AutoencoderEncoder compresses input → decoder reconstructs it; the bottleneck forces useful compression.
Sparse autoencoderAdds a penalty encouraging most of the compressed code's values to be near zero.
Variational Autoencoder (VAE)Makes the latent code a probability distribution, enabling new-sample generation.
Reparametrization trickA math trick that lets gradients flow through a random sampling step during training.
GAN (Generative Adversarial Network)Generator vs. discriminator, trained against each other until fakes are indistinguishable from real.
Minimax gameThe tug-of-war training objective: generator minimizes, discriminator maximizes, the same expression.

Learning Paradigms

Weakly-Supervised Learning

Getting pixel-perfect labels (exact outlines of every object) is expensive and slow. Weakly-supervised learning works with cheaper, coarser labels instead — like just "this image contains a cat," with no location information at all — and uses clever tricks to still recover fairly precise localization. The core trick: repurpose a network trained only for whole-image classification, and look at which regions of its internal feature maps were most responsible for that classification score.

TermPlain meaning
Strong vs. weak supervisionPixel masks / boxes (strong) vs. only whole-image tags (weak).
Priors & hintsExtra assumptions (typical object shape, size) that make weak labels workable.
Global Average Pooling (GAP)Averaging each feature map to one number, right before the final classifier layer.
Class Activation Map (CAM)Reusing the classifier's own weights to turn its feature maps into a rough localization heatmap — with no location labels ever provided.

Learning Paradigms

Self-Supervised Learning

A clever way to get "free" labels straight out of the raw data itself, with zero human annotation. You invent a pretext task — predict the missing piece, the next frame, whether two crops came from the same image — that the data can label automatically. The network learns genuinely useful features solving this made-up task, and those features are then reused for the task you actually care about. Contrastive learning is the currently dominant flavor: train the network so that two different views of the same thing end up with similar representations, while different things end up far apart.

TermPlain meaning
Pretext taskA made-up prediction task whose "labels" come free from the data's own structure.
Generation-based methodsPredict missing or future content directly (e.g. inpainting, future-frame prediction).
Context-based methodsPredict spatial relationships — e.g. the relative position of two image patches.
Contrastive learning / InfoNCE lossPull together representations of two views of the same sample; push apart representations of different samples.

Specialized Topics

Graph Deep Learning

Not all data is a neat grid (images) or ordered sequence (text) — social networks, molecules, and road networks are naturally a graph: a set of nodes connected by edges. Graph Convolutional Networks generalize the convolution idea to this irregular structure: instead of "average my neighboring pixels," each node updates its representation by aggregating information from its neighboring nodes, layer by layer, so information gradually spreads across the whole graph.

TermPlain meaning
Graph = (nodes, edges)The basic structure: a set of points and the connections between them.
Graph LaplacianA matrix encoding the graph's connectivity, used to define "smoothness" and convolution on a graph.
Spectral vs. spatial convolutionTwo mathematical routes to the same goal — filtering signals defined on a graph.
Graph Convolutional Network (GCN)Each layer mixes every node's features with its direct neighbors', then applies a learned transform.
GraphSAGELearns to aggregate a sampled neighborhood, scaling graph learning to huge graphs.

Specialized Topics

Known Operator Learning

This one is a signature research theme of your own professor (Andreas Maier). The idea: if you already know the exact mathematical formula for part of a problem — for instance, the physics of how a CT scanner reconstructs an image from X-ray projections — don't make the network re-learn that from scratch. Instead, bake the known, exact formula directly into the network as a fixed (non-trainable, or partially-trainable) layer, and let the network only learn what's genuinely unknown around it. This uses far fewer trainable parameters, stays more interpretable, and is provably at least as accurate as learning everything blindly — sometimes called precision learning.

TermPlain meaning
Known operatorA piece of the problem you already have an exact, hand-derived formula for.
Precision learningEmbedding that known formula as a fixed network layer instead of learning it from data.
Filtered back-projection as a layerA 100-year-old exact CT-reconstruction formula, reimplemented as fixed convolution + fixed matrix-multiply layers.
Variational networks / unrolled optimizationTurning an iterative classical algorithm into a fixed number of trainable network layers, one iteration per layer.
