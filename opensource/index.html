Open Source

Learning to work in public

My honest, in-progress log of becoming an open-source contributor — starting from zero, documenting every step, including the awkward ones.

Why I'm doing this

Three reasons

Reading real codebases

Course projects are clean. Production ML libraries are not. Contributing forces me to read code written by hundreds of people over years — a skill no course teaches.

Collaboration in public

PRs, code review, maintainer feedback — the exact workflow of any engineering team I'd join as a Werkstudent, practised in the open.

Giving back to my tools

My thesis ran on PyTorch and open datasets. Everything I've learned rests on open source. Contributing, even small fixes, is how that debt gets repaid.

Target projects

Where I'm aiming

Hugging Face Transformers
I use it daily. Starting with documentation improvements and "good first issue" labels — docs PRs are the standard entry path and maintainers actively welcome them.
PyTorch
The framework behind my published thesis. Longer-term target — the codebase is large, so I'm building up through issue triage and reproducing reported bugs first.
RecBole / recommender-systems libraries
Where my domain knowledge is strongest. A recsys library is the most realistic place for me to contribute actual features, not just fixes.
